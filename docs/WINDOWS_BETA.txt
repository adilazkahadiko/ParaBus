ParaBus Windows x64 v0.1.0-beta.4（2026-10-28）

公開Release: https://github.com/adilazkahadiko/ParaBus/releases/tag/v0.1.0-beta.4
脆弱性の非公開報告: https://github.com/adilazkahadiko/ParaBus/security/advisories/new

使い始める
1. 受け取ったZIPを右クリックして「すべて展開」し、新しい専用フォルダーへ展開します。
2. ParaBusフォルダー内の ParaBus.exe を開きます。ほかのEXEを開く必要はありません。
3. 通知領域の「PB」アイコンから操作画面を開きます。
4. SETUPで自分のDiscord Botと接続先を設定し、手動で接続します。
   開発者のTokenや設定は含まれていません。Bot TokenやSupport Bundleを他人へ送らないでください。
5. Mainの出力機器を選びます。Cueを使う場合はCue側の機器も選びます。
   Discordへマイクを送る場合だけPhysical InputとROUTEを設定し、TXを開始します。

Node.js等の開発ツールのインストールは不要です。Windows x64用です。
ASIOを使う場合は、機器メーカーの正規64bitドライバーを別途インストールします。
アプリはコード署名していません。SmartScreenが出た場合は、取得元を確認して判断してください。
OSの保護設定は変更しないでください。アプリ制御で起動を拒否される場合は、下の「既知の問題」を参照してください。

既知の問題
Discordからの受信データの届く間隔が大きく揺れると、受信音が一瞬途切れることがあります。
受信側の処理の停止やデータの欠けではありません。改善を検討しています。

Windows 11でスマート アプリ コントロールがオンの場合、同梱の署名のない音声DLLの
読み込みが拒否され、起動しないことがあります。2026-10-27にメンテナーのPCでbeta.2を使って確認しました。
状態はWindows セキュリティ → アプリ & ブラウザー コントロール → スマート アプリ コントロールの設定で確認できます。
Microsoftの案内: https://support.microsoft.com/ja-jp/windows/security/windows-security/app-browser-control-in-the-windows-security-app
現時点でParaBus側の回避策はありません。コード署名を検討しています。OSの保護設定は変更しないでください。
beta.2ではトレイに「初回導入が必要です」と表示されますが、再導入では解決しません。
beta.3以降では、拒否を判定できた場合にアプリ制御によるブロックとして通知します。

使い始めの確認
・起動してBotへ接続できるか、参加者の音がMain/Cueで聞こえるか。
・各ユーザーのVC MIXフェーダーとMIX ON/OFFが意図どおり効くか。
・必要ならTXと録音を試し、保存した録音を再生できるか。
・画面の分かりにくい点、音切れやノイズなど、気付いた点を教えてください。
問題が出たら、時刻・操作・使用機器・画面のBUILDを控えてください。
リセット前にSupport Bundleを保存し、内容を自分で確認してから必要な情報だけ共有してください。

終了する
録音を停止して保存完了を待ち、SETUPの「ParaBus を終了」を選びます。
設定ロックをOFFにし、表示中の障害を確認する必要があります。
ブラウザーを閉じるだけではアプリは終了しません。

beta.4の変更
・設定ロックを外しても、参加者の承認がリセットされなくなりました。
  FAULT（障害）の確認、本体の終了・再起動では、これまでどおりTrusted以外の参加者の承認をリセットします。
  FAULTの確認画面にも、承認がリセットされることを表示します。
・本体を再起動した後、開いたままの操作画面のタブには再読み込みの案内を出します。
  再起動を操作したタブ自身は、本体の応答が戻ると自動で再読み込みします。
  本体が止まっている間は、再接続の間隔を最大10秒まで徐々に伸ばします。
  認証に失敗した要求のログは、連続した分をまとめて記録します。
・LAN公開時、LANから状態を読み取る場合にも、操作画面の認証を必要にしました。
・Stream Deckなどの外部操作向けAPIの設計書 docs/EXTERNAL_CONTROL_API.md を同梱しました。
  機能はまだ実装していないため、外部操作には使えません。
・音声の信号処理、native部品、依存ライブラリ、Node.jsはbeta.3から変更していません。

beta.3の変更
・操作画面の接続先を制限しました。通常の設定で使えるのは127.0.0.1／localhost／[::1]と、
  LAN接続を有効にしたときにSETUPに表示されるLANのURLだけです。
  LANからPC名や古いIPアドレスで開くと拒否（403）されるため、表示されるURLを使ってください。
  許可するアドレスは起動時に決まります。起動中にPCのIPアドレスが変わった場合は、アプリを再起動してください。
・Bot Tokenの環境変数名はDISCORD_BOT_TOKEN、またはDISCORD_BOT_TOKEN_に
  英大文字・数字・アンダースコアを続けた名前に限ります。
  設定を手で別の名前に変更している場合は、操作画面から設定を保存できません。
  アプリを終了し、discord-bots.jsonのtokenEnvと.env（またはOS側）の対応する環境変数名を、
  Botごとに重複しないDISCORD_BOT_TOKEN_RX01などに揃えてから起動し直してください。
・操作画面をほかのページに埋め込めないようにしました。
・機器が外れたことを知らせる内部用の命令は、外部から受け付けないようにしました。
・操作画面の説明文を減らし、詳しい説明をマニュアルへ移しました。
・マニュアル・Discord設定・READMEなどの文書を更新しました。
・音声部品がWindowsのアプリ制御に拒否されたと判定できた場合は、トレイに専用の通知を出します。
  通常の読み込み失敗の通知も、ZIP版向けの案内にしました。
・音声デバイスがFAULTになったとき、理由の分類とhost APIをログに残すようにしました。
  Support Bundleには理由の分類とhost APIを残し、デバイス名やパス、エラーの原文は含めません。
・トレイからログをBOMなしUTF-8で追記するようにし、日本語の文字化けを修正しました。
・音声の信号処理、native部品、依存ライブラリ、Node.jsはbeta.2から変更していません。

この版について
Node.js 22.23.4を同梱しています。
旧private履歴の検証候補1058fb681f93で、2026-10-22に約1時間の音声・録音・Discord送信を確認しました。
この番号は公開履歴のcommitではありません。
タブレット操作は再設計待ちのため、この版では提供していません。
以前にTXで一瞬のノイズ・詰まりの報告があり、原因は未特定です。
旧private候補1058fb681f93での約1時間試験では問題の報告はありませんでした。正式な安定版ではないベータ版です。
segfault-handler除去・UI整理・タブレット提供停止・依存更新後の長時間実機試験は未実施です。
多人数・別機種・SoundGrid/LV1での本番実機確認は未完了です。予備の音声経路を用意してください。
旧版に含まれていた任意のsegfault-handler/StackWalker診断機能は同梱していません。
音声DLL・Rust EXEは出自とhashを記録して再利用しています。再ビルド済みとは扱いません。
音声DSP・native DLLは元候補と同じです。旧POST設定が残る場合はSETUPに確認・解除操作を表示します。
旧設定は自動変更しません。POST復旧で音が出る場合があるため、確認してから操作してください。
元の配布候補eb206444c332ではnative読み込みと実ParaBus.exeの起動・通常終了を確認済みです。
beta.2ではundici 6.29.1・brace-expansion 1.1.21へ更新し、VCマスターをMASTER ON / MASTER MUTEDと表示します。
音声処理・nativeは変更していません。beta.2のWindows ZIP版で、メンテナーが実Discordへの接続と音声の送受信を確認しました。
短時間の試験のみで、長時間の実機試験は未実施です。
BUILD COMMITと各部品のSHA-256は同梱のcomponent-provenance.jsonを参照してください。
