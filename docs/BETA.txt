ParaBus ベータ候補（2026-10-25 更新）

位置づけ
試用・フィードバックのための候補です。正式な安定版ではありません。
Windows実機で検証していますが、多人数・別機種・SoundGrid/LV1での本番実機確認は未完了です。
一般向けの実行版Releaseはまだ公開していません。
個別レビュー用Windows ZIPと対応ソースを用意しています。作成方法・配布構成は
SOURCE_RELEASE.md、CORRESPONDING_SOURCE.txt、REVIEW_PACKAGE.txtを参照してください。
第三者依存にはそれぞれのライセンスが適用されます。ルートのTHIRD_PARTY_NOTICES.mdを参照。
本文の1058fb681f93・2b920eb1aafd・ed4c57df4431は、旧private履歴での検証・部品取得IDです。
公開履歴のcommitとして探す必要はありません。配布物のBUILDと出自の記録はcomponent-provenance.jsonを参照。

最近の変更
・タブレット操作は再設計まで提供を停止。旧設定が有効でも専用リスナーは起動しません。
  試作コード・旧設定は保管し、デスクトップの設定保存では旧タブレット設定を変更しません。
・MIX / SETUP / ROUTEは重複する見出し・常設の説明を整理。詳しい使い方はマニュアルへ移動。
・参加者の操作をVC MIXへの送出フェーダー・MIX ON/OFFとして整理し、未使用のPOST表示を削除。
・SETUPの物理入力の集約メーターを削除。TXの確認には実際の送信メーターと聴感を使います。
・Node.jsは22.23.4以上23未満を必要とし、検証ZIPにも公式22.23.4を同梱。
・個別レビュー用候補2b920eb1aafdでは、旧StackWalkerを含む任意のsegfault-handler診断機能を除外。
  音声DLLは変更せず、元のLICENSE・対応ソース・部品の出自とhashを保持しています。
・旧POSTのレベル・ミュートが残っている場合だけSETUPに確認・解除操作を表示します。
  設定は自動変更せず、POST復旧で音が出ることを確認してから0 dB / ONへ戻します。
・配布候補は固定source checksum、native入力hash、上流package由来の記録を検証し、
  旧private Git履歴に依存せず対応ソースを組み立てます。案内名はREADME-FIRST.txtです。
・Discord送出時計にはperformance.now()を使用。固定依存@discordjs/voice 0.19.2へ
  scripts/patch-discord-voice.tsで変更を適用します。グローバルな時計やOS設定は変更しません。
既存の運用フォルダーには上書きせず、新しい専用フォルダーへ導入してください。

既知の制約
・以前の検証で、TXに一瞬のノイズ・詰まった感じが出て自然に戻るという報告があります。
  原因は未特定です。今回の約1時間の確認で報告がなかったことを、解決済みとは扱いません。
・Discord再接続時はTXを安全停止し、接続復帰だけでは自動再送しません。
  接続先と入力を確認したうえでTXを明示的に再開してください。再起動・自動再接続での無断送信はしません。
・RXとTXは独立です。TX停止表示でもRXからスピーカーへの出力は継続できます。
・User録音は個人のPRE、VC MIX録音はVCマスター前を使用します。
  VC MIX録音には個人の送出フェーダー・MIX ON/OFFが反映され、VCマスターの操作は反映されません。
・音源の無音とRXパケット途絶をカウンタだけでは区別できません。
・物理出力のnative underrunは直接見えません。破棄0でも実際の聴感確認が必要です。
・ASIOのwriteTiming=nullは仕様です。無音カット・補間・underrun単独で不合格にはしません。
・未署名の配布物ではOSの警告が出る場合があります。取得元を確認し、OS全体の保護は無効化しないでください。
・LAN画面は信頼できるLAN内だけで使用し、外部公開やポート転送をしないでください。

次の現場での報告
1. BUILD COMMIT、Windows、Main/CueのHost API・ドライバ・sample rate・ch数、参加人数を記録。
2. 実Discord経由の音源送出を確認。試験開始時刻・カウンタを残す。
3. 開始/30/60/90分にSupport Bundle。音源停止・参加離脱・機器/ミュート操作の時刻も記録。
4. 継続するプツ音、増える遅延、発言の欠け・古い音を聴感確認。聞いていない区間は未確認と記載。
5. 出力破棄・RX overflow・TX破棄は開始時からの差で報告。1分p95を平均して全体p95としない。
6. 障害時はリセット前にBundleを保存し、困難なら予備経路へ切り替える。故障状態のまま本番を続けない。
7. 録音保存完了後、実行PCのSETUP「ParaBusを終了」で通常終了。
