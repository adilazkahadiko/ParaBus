まず起動する

1
ParaBus.exeをダブルクリック

WindowsのテストZIPを専用フォルダーへ展開し、ParaBus.exeを開きます。アプリだけを別の場所へ移さないでください。

2
ParaBusアイコンを確認

タスクバー右端の通知領域にParaBusアイコンが残れば起動中です。

3
UIを開く

ParaBusアイコンをダブルクリックします。既定ブラウザーで操作画面が開きます。

Windowsはコンソール窓を出しません本体は通知領域で動作します。アイコンが見えない場合は通知領域の ^ を押してください。SmartScreenが出たら、取得元を確認したうえで詳細情報 → 実行を選びます。Botは未接続で待機するため、SETUPから対象Botを接続します。互換用のstart-router.cmdも使用できます。

Macの初回起動

macOSはテスト用パッケージです。実機での検証はWindowsほど行っていません。

ZIPは書き込み可能な専用フォルダーへ展開します。ParaBus.appだけを移動せず、runtime・scriptsなどと一緒に置きます。

  1. ParaBus.appをダブルクリック。警告が出たら完了で閉じます。
  2. システム設定 → プライバシーとセキュリティ → このまま開くで、信頼できるParaBusの起動を許可します。
  3. 必要ならもう一度ダブルクリックします。同じ展開フォルダーでは通常、2回目以降の許可は不要です。ブラウザーに操作画面が開きます。

Apple Developerの署名・公証は行いません。許可手順はAppleの初回起動案内も参照してください。OS更新や管理ポリシーによっては再確認が必要です。

初回起動後、展開フォルダー内だけのcom.apple.quarantine属性を解除します。Gatekeeper全体は変更しません。OSの隔離実行で隣のファイルが見えない場合は、runtime・scripts・ParaBus.appが入った展開フォルダーを選択してください。互換用のstart-router.commandも残しています。

タブレット操作

再設計のため、現在の版では提供していません。旧設定が残っていても専用ポートは起動しません。

入出力を確認する

INは受信音声です。参加者はALLOWするまで本線・Cueには出ません。Mainの経路が設定済みでも無音の場合は、ALLOW・ミュート・レベルと音卓側を確認してください。

入力デバイスはDiscordへマイクなどを送る場合に使います。受信だけなら不要です。入力の割り当てはROUTE、送信音量はMIXのTX MASTERSで操作し、TXは手動で開始します。

Mainと別の機器でCueを聞く場合は、Cueの出力デバイスを選びます。Mainと同じ機器を使う場合は、Cue欄でMainの空き出力chを指定します。

Discord接続を設定する

  1. SETUP → BOTSを開き、＋ RX、＋ TX、＋ RX+TXのいずれかを押します。
  2. カードの詳細で名前・役割・Server ID・VC ID・Tokenを入力し、使用へチェックします。
  3. 設定を保存を押します。保存だけでは接続しません。
  4. 各Botの接続 / 切断を明示的に押して操作します。

20台などを登録するときはBot Token をまとめて追加へ1行1Tokenで貼り付けます。空行・重複・形式不正行は飛ばし、合計24台までRXとして追加します。Server IDだけ1枚目から引き継ぎ、VC IDは事故防止のため空欄です。各VCを設定してから保存してください。

Botトークンを共有しないスクリーンショット、チャット、ソースコード、ログへ貼らないでください。設定ページのBOT TOKEN欄だけへ入力します。

IDをコピーできない場合

Discordの開発者モードを有効にすると、サーバーやボイスチャンネルの右クリックメニューからIDをコピーできます。Botには対象チャンネルの表示・接続・発言権限が必要です。

Discordを使わず画面だけ試す場合は3項目を空欄にします。16チャンネルのテスト音声で起動します。

まず1 Botで送受信

通常はRoleをRX+TX（双方向）にします。1 Bot・1 VoiceConnectionでDiscord音声の受信とGAME Stemの送信ができます。同じTokenをRXとTXへ重複登録しないでください。

複数Bot / RX最大24・TX最大22・合計最大24

SETUPのBOTSで＋ RX、＋ TXまたは＋ RX+TXで追加します。TX / 双方向BotはMONO / STEREOを選べます。

1 PCあたりRX最大24 Bot、TX最大22 Bot、合計最大24 Botです。DUPLEXはRX枠・TX枠を各1つ消費し、合計では1 Botと数えます。APEX 20チームはRX PCとTX PCを分離する設計です。すべて別のBot tokenを使い、チャットやJSONへtoken本体を貼らず、.envだけへ保存してください。

共通Server・Bot設定ファイル・ドライバ別の機器選択

初回のBot一覧は空です。共通Server IDを入力すると、未設定または前の共通IDを使っているBotへ反映します。別Serverを個別指定したBotは維持します。Serverが変わったBotのVCは空になるため、接続先を選び直してください。

Bot名は自由に変更できます。内部Profile IDは接続・Token・Sceneの参照に使うため、非表示の固定IDとして保持します。Bot設定の書き出しにはTokenを含めませんが、Server / VC IDは含みます。読み込みは編集一覧の置換だけで、自動保存・接続はしません。

機器選択はASIO / WASAPIなどのドライバ別に区切ります。「稼働中」に表示された機器とドライバが実際の使用先です。選択だけでは切り替わりません。

Mainと同じ機器でCueを出す（ASIOも対応）

SETUPのCue設定でMainの空き出力chを指定します。Mainと同じストリームを使うため、同じ機器を二重に開きません。Main本線・Direct Outと共有しない空きchと、そのchにつながったヘッドホン設備が必要です。2出力しかない機器で本線が1/2を使っている場合は共有Cueを作れません。

独立Cueデバイスを停止してから、SETUP中に設定してください。別のASIO機器を独立Cueとして同時に開く機能ではありません。Physical InputのASIOは既存のMainとの共有ストリーム方式を使います。

赤／青などのグループBusとDirect Out

ROUTEのグループBusでVCを選びます。各VC MIXのフェーダー・MUTE後の音声を合算し、さらにグループのフェーダー・MUTEを通します。グループもマトリクスからOutputへ割り当てられます。グループの入れ子には対応しません。

元のVCの出力先は自動では解除しません。二重に出したくない経路はマトリクスで解除してください。グループ構成は現在のセッション限りです。再起動後は作り直してください。Sceneだけで構成の復元はできません。

マトリクスのVC名を押すと参加者のDirect Out行が開きます。DirectはMONO表示で割り当て、既存のPRE/POSTを維持します（未設定はPRE）。PREのDirect OutはMIXのVC MIX送信ON/OFF・音量から独立しています。InputのTX送信は別のInput → TX Botマトリクスで設定し、物理OUTは使いません。

MIXではVCマスターの名前を押すと、そのVCの参加者へ切り替わります。1本だけのマスターも横いっぱいには広がりません。

稼働状況とEventを確認する（STATUS）

LOG

LEVELでINFO / WARNING / CRITICALを選び、FILTERへBot名、Scene、Device、Recorderなどを入力して絞り込みます。表示対象は状態APIが保持する最新100件です。

ログ消去はSETUP / READY中だけ確認ダイアログで確定すると既存Eventを消去しますが、消去操作そのものはWARNINGとして残ります。Bot Tokenと音声内容は記録されません。

Support Bundle · 障害調査用ZIP

障害時は実行フォルダではなくSupport Bundleを共有する実行フォルダ全体、.env、Bot設定原本、録音ファイルをZIPにして共有しないでください。Support BundleはON AIR中も作成できます。
  1. STATUS → Support Bundle · 診断を開きます。
  2. ログ日数（既定7日、1〜30日）を選び、Support Bundleを作成を押します。ON AIR中・録音中も使用でき、音声・TX状態は変更しません。
  3. 出力先を開くからsettingsRoot/support/の生成ZIPを確認し、その1ファイルだけを調査担当へ共有します。フォルダを開けない環境では、作成結果に表示されたパスを使ってください。

ZIPには最近の運用ログ、存在するトレイconsoleログ、build commit・起動時PC role・UTC起動時刻、Bot/TX/RX・drop・xrun・録音Queueの診断統計、Bot role・送信先区分・有効状態・台数、Node/OS/CPU/メモリ・native依存状態を含めます。Token・.env・Bot設定原本・録音・Scene・参加者profile原本は含めません。Discord ID・参加者表示名・Guild名・VC名はBundleごとに匿名化し、対応表は付けません。

Bot profileIdと運用者設定labelは残ります。機密の名称を付けないでください。未知のログ自由文は匿名イベントIDになり、原文の復元はできません。consoleログは更新日で選択され、末尾最大5MiBだけを収集します。途中から始まる最初の行は捨て、切り詰めと元サイズをbundle-info.jsonへ記録します。

参加者とVC MIXを操作する（MIX）

  1. MIXを開き、Bot表示フィルターまたは参加者検索で対象を選びます。
  2. IN（承認前）のPeak/RMS・Peak Hold・Clipで受信を確認します。INは送信量のメーターではないので、MIX OFFでも動きます。
  3. 各ストリップのVC MIXフェーダー、MIX ON/OFF、CUEを操作します。
  4. 全VCのMasterは常時表示されています。
  5. ROUTEでVC MIXの出力先やグループを確認します。

Receiver Owner

VCごとに1台のBotだけが受信します。自動切替はしません。受信Botが停止した場合は、そのVCだけが無音になります。切り替えはROUTEのReceiver Ownerで手動で行います。

VCグループ（グループBus）の作成・削除

ROUTE → VC GROUPで新規グループ名を入力し、グループを適用を押します。削除はグループを選んでグループを削除を押します。含めるVC MIXも同じ場所で選択できます。

ON AIR中は構成を固定グループの適用・削除とPolicy変更はできません。参加者Send、Mute、PFL、Bus Masterは引き続き操作できます。

メイン出力のテストトーン（MAIN OUTPUT TEST）

OUT 1〜のボタンで、そのchだけへ1 kHz / −24 dBFSを送ります。もう一度押すと停止します。SoundGridとLV1のpatch順確認に使用します。

実deviceでは実際にtoneが出ますモニター音量を下げ、SETUP中に1chずつ確認してください。ON AIR中とFAULT中はtest toneを開始できません。

入力チャンネルをTX Botへ送る

  1. SETUPでPhysical Inputのデバイスと入力ch数を選び、開始します。
  2. Bot設定でMONO / STEREOを指定して接続します。
  3. ROUTEのTX ASSIGNMENT（Input Ch → TX Bot）で交点を押します。MONOは1ch、STEREOは選んだchと次のchをL/Rに使います（例：IN 3 / 4）。同じ入力を複数Botへ割り当てられます。
  4. 入力を選んだだけでは送信しません。送信先VCを確認して、MIXのTX MASTERSで該当Botの「送信OFF」を押し、確認して送信ONにします。

InputのPOST音声を直接送信するため、Main Output・Direct Out・内部Busの割り当ては不要です。入力変更は停止中のみ。最後の1chだけではSTEREOにできません。緊急停止・切断・入力消失から自動再開しません。入力割り当ては現在のセッション内で有効です。

出力を割り当てる（ROUTE）

ROUTEのマトリクスは、行がVC MIX・VC GROUP・参加者Direct Out、列が選択したMain Outputの出力chです。CUEはこのマトリクスとは別経路です。

ROUTE → VC名をクリックして参加者のDirect Out行を開き、OUTとの交点で割り当て／解除します。既存のPRE/POST設定を維持し、未設定はPREです。他経路が使っている出力への割り当ては拒否します。

項目動作
OUT 1〜 / 出力なし物理出力chへの割り当て／解除。交点ボタンを押して切り替えます
PREChannel Faderの影響を受けない。LV1側mix、multitrack向け
POST（既存設定の互換用）保存済みのチャンネル音量・Muteを反映する経路。MIX画面にはPOST専用操作を表示しない。VC MIX送信の音量・ON/OFFとは独立
CUEマトリクス右端のCUEボタンでその行の音声を試聴
MappingはSETUPで確定するON AIR中は出力先、PRE / POST、test toneの変更が拒否されます。deviceのch数を超えるOUTは選択できません。

メーターと数値の読み方

PK dBFS現在のsample peak。0 dBFSを超えないようにする。
LUFS-M約400 msの瞬間ラウドネス。
LUFS-S約3秒の短時間ラウドネス。
LUFS-I開始またはresetからの積算ラウドネス。
配信運用の目安: −18 LUFS現在のUIでは配信用の運用基準として表示しています。配信先の規定がある場合は、その規定を優先してください。
  • 緑: 通常範囲
  • 黄: peakが高め。上げ過ぎに注意
  • 赤: 0 dBFS付近。fader / send / masterを下げる
  • −∞: 実質無音
  • PK dBFSはtrue peakではありません。true peak実装まではdBTPと読み替えないでください。

ミキサー操作

VC MIXへの送信音量

参加者の縦faderを動かすか、その下の数値欄へdB値を入力します。数値欄は0.1 dB単位で入力でき、Enterで確定します。

VC Send

各UserをVC Busへ送る量です。新規Discord Userは安全のため −12 dB から始まります。faderと数値入力のどちらでも操作できます。

参加者の送信ON/OFF

参加者ストリップのMIX ON/OFFは、その参加者から選択中のVC MIXへの送信を操作します。PREのDirect Out・個人CUE・個別録音には影響しません。INメーターは受信音声を示すため、MIX OFFでも動きます。緊急時は画面上部のEmergency Muteを使います。

PFL / CUE

個人CUEはVC MIX送信のON/OFF・音量から独立し、VC MIX CUEはVC MasterのMute・Fader前で試聴します。本線の音量は変わりません。未承認の参加者・緊急停止はCUEでも無音。VC MIX CUEにはOFFのVC Sendを含めません。

VC Bus Master

配信用mono bus全体のlevelです。LUFS-Iとpeakを見ながら調整します。Safety Limiterは通常ONのまま使用します。

入力音声をDiscordへ送る（TX）

  1. SETUPで入力デバイス・ch数と、Botの名前・TXまたはRX+TX・MONO/STEREO・接続先VCを設定します。
  2. ROUTEのTX ASSIGNMENT（Input Ch → TX Bot）で入力を割り当てます。MONOは1ch、STEREOは連続2chです。物理OUTは経由しません。
  3. MIXのTX MASTERSでBotごとのフェーダーを調整し、「送信OFF」を押します。送信先VCと入力を確認して開始すると「送信ON」になります。
  4. 個別停止は「送信ON」、全停止は同じ欄の「全TX停止」です。全停止には確認を挟みません。

TXフェーダーは入力のLEVEL・MUTE後に適用する、Botごとの独立した音量です。同じ入力を複数Botへ送っても他のBotの音量や録音PREには影響しません。範囲は−90〜+12 dB、−90 dBは無音です。PeakメーターはTX音量を反映した送信信号を表示します。フェーダーを動かすだけでは送信しません。

固定のTeam / Interview / Spare区分、TX STEM、ARMED/LIVE選択パネルはありません。設定したTX / RX+TX Botだけを自由な名前で表示します。旧設定の区分値は互換性のため保持しますが、この画面では使いません。旧SPARE役割はRXとして表示しますが、既存の受信担当を変えないため、内部では待機役割を保持します。

入力割り当てとTX音量は現在のセッション内で有効です。再起動後は入力を再度割り当ててから開始してください。TX音量の初期値は0 dBです。

勝手に再開しませんVC / IPC切断、VC変更、Emergency Muteで送信を停止します。復旧後も手動の送信ONが必要です。送信中とON AIR中は入力割り当てを変更できません。

通常の全TX停止はIPCを維持します。STOP前に送信待ちとなった短い末尾音声は流れる場合があります。

RX / TXは別PCを推奨Emergency Mute・停止送信の障害時や送信待ちが256KiBを超えた全TX停止では共有IPCを切断することがあります。同じAdapterのRX / RX+TX受信も一時停止します。
Feedback Loopを防ぐ受信音声を外部ミキサーから入力へ戻す場合、同じVCの音声がそのVCへ戻らないようにしてください。

WAV録音

  1. SESSIONを開きます。
  2. 録音する音声で、必要なMain Output、VC MIX、User / Inputを個別にチェックします。各一覧で「すべて選択／解除」も使えます。
  3. 選択数を確認し、録音を開始で確認します。Userだけ、VC MIXだけの録音も可能です。
  4. 終了時は録音を停止を押し、保存完了（待機／IDLE）まで待ちます。

保存先はプロジェクト内のrecordingsです。48 kHz / mono / 32-bit float WAVで、Trackは録音開始時に固定されます。

チェックした音声ごとに、1chの48 kHz Float WAVを保存します。Output 1/2は2つのmono WAV（2ファイル）です。User / InputはTrim・HPF・Compressor後、フェーダー前（PRE）の音声で、chのフェーダー・ミュートは反映しません。VC MIXは各参加者のVC送信（MIX ON/OFF・送信音量）を反映し、VC Masterのフェーダー・ミュートは反映しません。PENDINGの参加者と緊急停止中は無音です。無音による自動除外はしません。途中参加のUserは自動追加せず、録音中／保存中は対象を変更できません。DROPPEDは録音で欠落したブロック数です。対象が消えた場合は、次の開始前に選び直してください。本線やCueの出力は録音操作で変更されません。

「本体を再起動して反映してください」と表示された場合は、出力・録音を止められるタイミングでSETUPから本体を再起動します。録音はSESSIONへ統一しました。Main Outputを1つ選び、VC MIXやUser / Inputですべて選択すると従来のカテゴリ全件指定に相当します。

DROPとFAULTを確認QueueのDROPが増えた場合、またはRecorderがFAULTになった場合は録音だけが停止します。配信音声は継続します。disk空き容量とFolderを確認して新しいSessionを開始してください。
長時間録音1 WAVが4 GiBへ達する前に安全停止します。現バージョンは自動file splitを行わないため、長時間番組では途中でSessionを分けてください。

Sceneを安全に保存・呼び出す（SESSION · SCENE）

現在のMixを保存する

  1. SESSIONを開きます。
  2. 現在のMIXを新しいSceneに保存で名前を入力して新規保存を押します。
  3. 保存済みSceneの選択欄へ名前が表示されたことを確認します。

保存対象はchannel順・表示名・Trim・Fader・Mute・VC Send、Bus Master / Mute / Compressor / Limiter、Matrix gain / muteです。Bot token、出力device、Bot接続先、Guild / VC割当は保存しません。上書き・削除は元に戻せません。設定ロック中やFAULT時は操作できません。

SceneをRecallする

適用するとMIXが変わるため、先に変更内容を確認してください。Recall前に必ずPreviewを表示します。保存後に参加したUserは対象外として表示されます。

  1. 保存済みSceneを選び、変更を確認を押します。
  2. 差分と保護/ロックを確認します。
  3. 適用を押し、適用件数を確認して承認します。
結果意味
APPLY確認後にScene値へ変更されるparameter
RECALL SAFE右側で保護されているため、現在値を維持するparameter
SAFETY LOCK現在のGlobal Stateでは変更を許可しないparameter。例: ON AIR中のLimiter OFF

Recall Safe

SESSION → RECALL SAFEを開き、検索して対象へチェックします。保護編集は設定ロックOFF・FAULT以外で行います。Previewにも保護状態が反映され、保護するだけでSceneをRecallすることはありません。

Sceneを選ぶだけでは音は変わりません必ず差分Previewと確認を通ります。FAULT中はRecallできず、ON AIR中はScene削除もできません。

安全状態の確認と監査ログ

画面最上部でシステム、受信、出力、設定ロック、緊急停止の状態をまとめて確認できます。STATUSのLOGではEventが新しい順に表示され、消去操作そのものも監査Eventとして残します。

安全機能

  • Emergency Muteはdirect / bus / matrixの全出力を即時無音にする。
  • Emergency Mute解除、ON AIR遷移・解除、Scene recallには確認操作が必要。
  • 出力device loss時は勝手なfallbackをせずFAULTへ入る。
  • FAULT確認後もEmergency Muteは維持し、出力確認後に別操作で解除する。
  • ON AIR中はdevice、output mapping、VC assignment、Bus構造、Scene削除、Limiter OFFをlockする。
  • Discord / Adapterが切れたsourceはsilenceになり、stale表示される。
  • 切断中のOpusを後から再生しない。古い会話はdropする。

終了・ログ・保守

再起動と終了

Windows・Macとも、実行PCのSETUP → ParaBus を終了を押して確認します。設定ロック（ON_AIR）中、FAULT中、録音・保存処理中は拒否されます。CoreのAudio I/Oを閉じ、Adapter・ランチャーが正常終了します。Windowsのトレイも消えます。LAN接続した別PCからは終了できません。

SETUP → ParaBus本体を再起動は、BotとAudio I/Oを停止して本体を起動し直します。再起動後、Botは未接続で待機し、CUEと物理I/Oは自動では開始しません。拒否される条件は終了と同じです。

Windowsではトレイの終了も同じ条件で停止します。ブラウザーのタブを閉じただけではアプリは停止しません。強制終了時の子プロセス監視もありますが、通常は終了ボタンを使ってください。録音中の強制終了はファイルを損なうおそれがあります。

ログ

WindowsはParaBusアイコン → ログを開く。Macは展開フォルダーのlogs/router.logへ起動中も追記します。

運用ログはlogs/operational-YYYY-MM-DD.jsonlへ実行中も追記されます。終了を待つ必要はありません。障害時は実行フォルダではなく、診断画面で作成したSupport Bundleだけを共有してください。
